1. INTRODUCTION                                           *lvim-fuzzy-intro*

lvim-fuzzy is the fuzzy search ENGINE of the lvim-tech set in Neovim. lvim-picker
and lvim-cmp both rank through it.

The engine is lvim-fuzzy-core (Rust), the same one the terminal finder
lvim-fuzzy-cli runs on, so a query ranks the same in the picker, in completion
and in the terminal. This plugin is a thin C ABI over core (`native/`, a shared
library loaded IN-PROCESS via LuaJIT FFI) and the Lua API on top.

The Lua<->native boundary is COARSE: a candidate set lives in a native context
(|lvim-fuzzy.prepare|, |lvim-fuzzy.blob_new()|), and every keystroke is a
SINGLE FFI call carrying only the query and returning the ranked indices. While
the query only grows, the next search reads only the previous matches.

The native library is REQUIRED (ABI 7): there is no pure-Lua matcher, and an
older library (ABI 1-6, which had a matcher of its own) is refused.

The result order is TOTAL and deterministic: score descending, then the
shorter candidate, then the earlier one.

2. QUERIES                                              *lvim-fuzzy-queries*

The defaults are lvim-fuzzy-cli's (and fzf's extended search):

  conf ui     both terms, in any order (a space is AND)
  'exact      the exact substring
  ^src        starts with src
  .lua$       ends with .lua
  !test       does not contain test
  lua | rs    either
  fb / FB     smart case: lower case folds, a capital is kept
  cafe        café too (Latin letters match their accented forms)

Every search call takes an optional `opts` table (|lvim-fuzzy-opts|) over the
config; lvim-cmp passes `{ extended = false, case = "ignore" }`.

==============================================================================
3. SETUP                                                  *lvim-fuzzy-setup*

Calling setup() is optional. The defaults:
>lua
    require("lvim-fuzzy").setup({
      library_path = nil,     -- nil = probe $LVIM_FUZZY_LIB, native/build/,
                              --       native/target/release/
      max_results = 1000,     -- results returned per query (0 = no cap)
      case = "smart",         -- "smart" | "ignore" | "respect"
      extended = true,        -- fzf's extended syntax
      exact = false,          -- every term an exact substring
      normalize = true,       -- `cafe` finds `café`
      scheme = "default",     -- "default" | "path" | "history"
      typos = 0,              -- characters a fuzzy term may miss, or "auto"
      exact_window = nil,     -- widest window scored exactly (nil = default)
    })
<
                                                          *lvim-fuzzy-opts*
The search keys (case, extended, exact, normalize, scheme, typos,
exact_window) are the defaults of every call; a call's `opts` table overrides
them. `opts.scope` ("all", "line", "path", "file") says what a grep result
(`path:line:text`) is searched by; "file" reads the file and takes every term
as an exact substring.

4. API                                                      *lvim-fuzzy-api*

                                                        *lvim-fuzzy.prepare*
require("lvim-fuzzy").prepare({candidates}, {opts}) → ctx
    A native context for a list of strings. Every candidate is kept (an empty
    one too), so result indices are indices into {candidates}. {opts} is what
    |lvim-fuzzy.match| uses when it is given none.

                                                          *lvim-fuzzy.match*
require("lvim-fuzzy").match({query}, {ctx}, {boosts}, {opts})
    → results, count, total
    `results[k] = { index, score }` (1-based index), best first, at most
    `max_results`; `total` counts every match. An empty query is the whole set
    in source order. {boosts} (optional, parallel to the set) is added to each
    candidate's score before ranking; ties keep the engine's order.

                                                         *lvim-fuzzy.append*
require("lvim-fuzzy").append({ctx}, {more}) → count
    Grow the set; only the new candidates cross.

                                                    *lvim-fuzzy.match_async*
require("lvim-fuzzy").match_async({query}, {ctx}, {cb}, {opts})
    |lvim-fuzzy.match| on a scheduled tick; `cb(results, count, total)`. A
    newer request supersedes a pending one; an identical one coalesces.

                                                         *lvim-fuzzy.filter*
require("lvim-fuzzy").filter({candidates}, {query}, {opts})
    One-off rank without a kept context.

                                                           *lvim-fuzzy.free*
require("lvim-fuzzy").free({ctx})
    Release the native memory now (otherwise the GC does). Safe twice.

                                                      *lvim-fuzzy.positions*
require("lvim-fuzzy").positions({text}, {query}, {opts}) → integer[]?
    The scored alignment as 1-based BYTE columns, ascending (every byte of
    each matched character) — what a menu highlights. Nil on a non-match.

                                                     *lvim-fuzzy.highlights*
require("lvim-fuzzy").highlights({text}, {query}, {opts}) → integer[]?
    The alignment plus every other occurrence of each term, as 0-based
    CHARACTER indices — what a list highlights. Nil on a non-match.

                                                      *lvim-fuzzy.blob_new()*
require("lvim-fuzzy").blob_new() → blob?
    A context fed with a process's raw output: `blob_append(blob, bytes)`
    (any chunking, split on "\n", empty lines skipped), `blob_flush(blob)` at
    the end of the stream, `blob_count(blob)`, `blob_text(blob, idx)`,
    `blob_match(blob, query, cb, opts)` (on a scheduled tick, `cb(results,
    count, total)`; a newer match on the same blob supersedes it) and
    `blob_free(blob)`. Nil when the library is not loaded.

                                                        *lvim-fuzzy.backend()*
require("lvim-fuzzy").backend()  → "native-avx2" | "native-scalar" | "none"

Other introspection: `native_loaded()`, `load_error()`, `library_path()`,
`abi()`, `native_abi()`. `has_append()`, `has_chunk()`, `has_par()`,
`has_blob()` and `has_boost()` remain from ABI 1-6 and equal
`native_loaded()`.

==============================================================================
5. BUILDING THE NATIVE LIBRARY                            *lvim-fuzzy-build*

>sh
    sh native/build.sh
<
Needs a Rust toolchain (cargo). The first build fetches lvim-fuzzy-core from
GitHub, pinned to a commit in `native/Cargo.toml`. The result is
`native/build/liblvimfuzzy.so` (`.dylib` / `.dll`). The compile cache goes to
$CARGO_TARGET_DIR when it is set (lvim-pack sets it outside the plugin).

==============================================================================
6. HEALTH                                                *lvim-fuzzy-health*

`:checkhealth lvim-fuzzy` reports whether the library is loaded (and why not),
its path and ABI, whether the CPU runs the engine's AVX2 paths, config
validity, and a sample query.
